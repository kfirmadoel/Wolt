# Team review and submission

[PR 31](https://github.com/kfirmadoel/Wolt/pull/31) is the single review for the complete Exercise 5 branch, `WOLT-167-Mobile-Storefront-Menus`, with `main` as the merge target. It includes parts 1, 2 and 3 and the required Exercise 4 website integration. The older branches do not need to be merged separately.

## Review the result

Start with the [project README](../README.md), then follow [Build and run](run.md). Read [Application flows](flows.md) for screenshots, observed results and any remaining manual checks. Review the actual changes in the PR, including the backend, both clients, Docker configuration and documentation.

An optional joint walkthrough can cover three main flows:

- Register with a picture, log in, browse and search, and switch the theme.
- Create, edit and delete a temporary restaurant and dish; refresh the other client to check the shared data.
- Place an order, edit it, check it in the other client and delete it after confirmation.

Both other team members must review the PR, raise any issues and approve the corrected result before merging into `main`. Do not record an approval on someone's behalf. In Jira, identify the reviewers and who moves the tasks to Done. Keep the sprint, Scrum Master and meeting records accurate, including the outcomes of the required status meetings. These requirements come from Exercise 5, pages 1 and 3–4; the status meetings are required at least twice a week.

## Submit to the course

Keep the repository private and verify that the checker account published by the course has viewing access to both GitHub and Jira. The repository contains the code, Compose configuration, README and `wiki` documentation with screenshots.

Upload a separate file named `details.txt` to the Moodle submission box. Use English only: one line per submitter containing their full name and ID, followed by the GitHub repository URL on the last line. Separate name words and the ID with single spaces. Do not add extra spaces, blank lines, headings or explanations. Keep the actual names and IDs out of the repository.

Exercise 5, page 4 specifies this format and a 20-point deduction for a missing or incorrectly formatted file. Page 2 specifies the `wiki` folder, full Compose run instructions and the main application flows with suitable screenshots. Team review, access checks and the Moodle upload must be completed by the team; this document does not record them as done.
